## Completed in this continuation

- **Increment 2, Task 3: managed model identity lifecycle** (`DOC-036`; foundation for `DOC-020`, `AG-003`, `AG-016`). Host assigns a model GUID for approved real `NewPart`, persists `Pending` before dispatch, gives managed sketches a logical output GUID and pending binding, advances model revision/status after successful managed mutations, stores path/SHA-256 after save, and marks uncertain outcomes without retry. Execution IDs stay out of serialized plans and parameters. Preflight keeps explicitly opened existing parts read-only until an approved managed-copy path is implemented.
- The production Host injects its SQLite reference store into `SolidWorksBridgeFacade`. Managed `NewPart` adds `SolidWorksCadAgent.ModelId` with `Add3(...OnlyIfNew)`, reads it back using `Get6`, and closes the newly-created document on mismatch. `OpenPart` reads property values on the STA, then checks registry ID/path/file hash outside the COM callback and binds only after validation. Registered paths missing their property, unregistered IDs, ID/path collisions and hash mismatches fail closed. Legacy documents without managed records remain unstamped and use the old open path.
- Updated `CAD_AGENT_ARCHITECTURE.md`, capability evidence (`DOC-036`, E15), this handoff and the implementation plan. No planner schema, historical plan JSON, native reference-token or user-model editing semantics changed.
- **Increment 2, Task 4: managed sketch reference capture and resolution** (`DOC-020`, partial `AG-016`). `CreateSketch` checks its pending binding before native creation, captures `ActiveSketch` with `GetPersistReference3` on the STA, copies and stores the bytes after the callback, and returns only the logical `entityId`. Capture/storage failure after creation returns a structured uncertain outcome, stopping the Host plan. The Bridge resolves a sketch ID only against the bound managed document/configuration; it validates the SOLIDWORKS 2020 `ProfileFeature` wrapper and its `Sketch` specific feature. Invalid, suppressed, deleted and wrong-kind results fail without a name/index/selection fallback. Unmanaged `CreateSketch` behavior remains compatible. Changed `SketchCommandHandlers.cs`, `SolidWorksBridgeFacade.cs`, added `References/SolidWorksReferenceResolver.cs` and `SolidWorksReferenceResolverTests.cs`, and extended `ModelReferenceCapabilityTests.cs`.
- **Increment 2, Task 5: negative native sketch-reference acceptance** (`DOC-020`, `DOC-036`, `AG-016`). Extended `ModelReferenceCapabilityTests.cs` with a same-named sketch in a second owned document, a byte-identical manual file copy carrying the same managed ID, and deletion of the owned sketch. The fixture checks that failed resolution leaves the last token/status unchanged and creates no replacement geometry. It exposed a real Bridge bug: a rejected `OpenPart` cleared the original bound model ID before the copied file was validated. `SolidWorksBridgeFacade.cs` now leaves the current identity intact until `BindPendingOpen` succeeds. Wrong-document errors now identify the `Resolve` stage; native status appears once in the diagnostic detail. No schema or persisted-plan semantics changed.
