# Versioned CAD plan v2 release readiness

Reviewed 2026-10-08 against branch `feature/v2-face-sketches-and-finishing`, HEAD `dfa309e568affaa20d2787b745f9d14bc3586612`, including uncommitted 7d-g5a–g5d work. This is a source review, not release authorization or a claim about installed binaries. The repository also uses “V2” for desktop, image-intake and Android milestones that still run the legacy CAD job path; this review concerns `planVersion: 2` execution.

## Decision

**Do not enable v2 job approval or advertise versioned CAD execution yet.** `JobCoordinator` persists normalized v2 candidates in `AwaitingClarification` with `PlanValidated=false`, rejects v2 in `ApproveAsync`, and has only a v1 `ExecuteApprovedWithinGateAsync` loop. Current production planners do not implement `IVersionedCadPlanningProvider`. Isolated Host boundaries can dispatch NewPart and CreateSketch, while the third AddRectangle step has preparation only. Direct Bridge v2 Extrude has bounded native evidence, but no Host v2 feature dispatch or end-to-end approved job exists. `CadPlanV2ExecutionReadiness` is review-only, takes caller-supplied execution/model IDs and refuses SavePart. These are intentional gates, not a configuration switch.

The earliest sensible milestone is a **private, opt-in v2 protocol pilot** for a newly owned part: NewPart → Top Plane CreateSketch → AddRectangle → ExitSketch → explicitly referenced boss Extrude → rebuild/measure → non-overwriting SavePart. Keep legacy v1 jobs available. This pilot does not claim conversational edits, arbitrary sketch profiles, cuts, images-to-v2, simulation, face selection, assemblies or drawings. A wider user-facing v2 release should additionally prove at least one useful multi-feature workflow (for example a plate and through-hole) with explicit cut direction and the same verification/recovery standard. Scope must be reflected in planner exposure and UI wording.

## Release-blocking work, in dependency order

1. **Consolidate and review the source baseline.** g5a–g5d and prior native fixture changes are uncommitted; preserve the unrelated `PrismaticCapabilityTests.cs` whitespace. Review the full intended diff, commit source/tests/docs, and retain a known revision for every native result. This is a reproducibility prerequisite, not a reason to open the v2 gate.
2. **Finish the first vertical mutation chain.** Correlate and atomically commit the Prepared no-output AddRectangle attempt (g5e), then handle ExitSketch and v2 Extrude under the same current-job/revision/plan-hash/model-owner guards. Determine whether ExitSketch is a mutation attempt or a guarded state transition, and record the decision before wiring it. The v2 feature result currently exposes a display `featureName`, not durable feature identity; the pilot may omit future feature editing but must not treat that name as an edit reference. Every ambiguous result or failed durable commit must stop replay; startup recovery must close Prepared attempts before further execution. Confirm behavior when native mutation succeeds but Host persistence fails.
3. **Complete artifact finalization and verification.** Bind v2 SavePart to the existing Host workspace, path, overwrite and approval policies; `CadPlanV2ExecutionReadiness` currently rejects it. Persist the saved path and content hash against the owned model, verify that the file corresponds to the intended model, then reopen/rebuild an owned artifact. Compare measured X/Y/Z dimensions, body/feature state and errors with the approved plan; current `JobCoordinator.VerifyAsync` checks only one body, positive extents and no rebuild errors, so it could accept the wrong-size part. Define tolerances and expected coordinate frame for this pilot. Do not report success based only on handler return JSON.
4. **Connect the coordinator, then the planner.** Build a v2 path through revision-bound approval, the existing execution gate, cancellation, command/verification history and ReadyForReview transition. Whole-plan readiness must use the current persisted job and supported release subset, not caller-supplied JSON or IDs as authority. Initially use a fixed/opt-in v2 planning provider or deterministic acceptance plan; production OpenAI and deterministic providers are currently v1 only. Expose only the shapes the coordinator can execute. Keep simulation explicitly unsupported until it models the same v2 references and geometry.
5. **Prove release behavior end to end on SOLIDWORKS 2020 SP0.0.** Run the approved pilot through the actual Desktop/Host/Bridge path, not direct Bridge calls or fake executors. Test explicit approval and zero mutation before it; dimensions, sketch and feature readback; save/reopen and artifact hash; wrong active document, stale revision, cross-job model, duplicate attempt, invalid plan, cancelled job, overwrite refusal, COM failure and restart after Prepared/uncertain mutation. Use only owned documents and restore the original session. Repeat the successful scenario and one controlled failure with fresh job IDs. Record native TRX/artifact hashes and installed source revision. The current E33 native result covers only isolated NewPart/CreateSketch; E23 covers direct v2 Extrude.
6. **Package and stage a reversible rollout.** Run both interop build modes and full automated suites, resolve or run the known `HttpListener` platform-sensitive test on a supported host, validate a native Release bundle, back up `jobs.db`, and stage binaries side by side. Schema v6 is additive, but an older Host rejects a newer `user_version`; rollback therefore requires a database plan, not just replacing EXEs. Test restart, old v1 plans/jobs and API/Android compatibility against the staged build. Roll out to the one SOLIDWORKS 2020 workstation first, with v2 opt-in and a documented disable path; widen only after the native pilot and real user workflow pass.

## Things that can follow the first release

Broad sketch primitives, a versioned CutExtrude with body-side direction, semantic face/edge selection, driving dimensions and conversational edits, image-to-v2 planning, simulation parity, cross-version certification, assemblies and drawings are separate capability milestones. Their absence must be stated in the product scope, not worked around with implicit current selection or a misleading planner prompt. If “v2 release” instead means only shipping the current desktop/Android interface with legacy CAD execution, use the existing app release checklist; the versioned CAD path must remain off.
