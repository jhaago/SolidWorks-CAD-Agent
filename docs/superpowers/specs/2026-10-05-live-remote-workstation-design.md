# First live Remote Workstation version

Date: 2026-10-05
Status: Approved by Jordan on 2026-10-05
Windows branch: `feature/v1-solidworks-2020`
Android branch: `feature/android-v0`
Parent design: `2026-10-04-android-remote-workstation-design.md`

## Goal and agreed direction

Replace the simulated desktop with the real Windows desktop inside the existing
Android app. Jordan must be able to view and manually operate the home PC while
away from home. Preserve the demo as a separately labelled option.

Jordan accepted Tailscale for the initial version but is concerned about needing
an additional application. Tailscale supplies connectivity only. Our software
owns pairing, authorization, capture, input, session state and stop controls.
The application protocol must use an ordinary HTTPS endpoint without Tailscale
SDKs, accounts, device identifiers or APIs in its domain contracts. A future
VPN or authenticated relay can supply that endpoint without changing input or
session rules. Transport independence does not mean a public relay is already
implemented or safe to deploy.

Do not merge either branch to main. Native SOLIDWORKS geometry verification is a
separate outstanding Windows gate; remote development does not verify it.

## Connection approaches

1. **Selected: private Tailscale HTTPS endpoint.** Install Tailscale separately
   on Windows and Android. Tailscale Serve forwards HTTPS within the private
   network to our new loopback service. This avoids running our own public
   relay for this milestone and keeps the existing CAD Host private.
2. **Future: our own Internet gateway/relay.** More integrated installation, but
   requires hosted infrastructure, authentication, encryption, operational
   maintenance and independent testing. It is outside this implementation.
3. **LAN-only connection.** Smaller setup, but does not meet the requested
   away-from-home use case and is not the chosen deliverable.

Use Serve, not publicly accessible Funnel. The setup guide gives exact commands
after the service port is implemented and tested. No router port forwarding,
automatic VPN installation, account creation or silent network changes.

## Windows components

Add a separate .NET Framework 4.8 Windows executable, consistent with the
existing Windows build and runtime. It runs in the signed-in interactive user
session, not inside the SOLIDWORKS COM bridge or as a system service.

- A small Windows Forms control window exposes pairing, paired-device revocation,
  current connection and a prominent Stop Remote button.
- A loopback-only HTTP server exposes versioned remote endpoints. It refuses
  non-loopback listener configuration. Tailscale Serve is the external HTTPS
  boundary; application credentials are still required behind it.
- A platform-independent session coordinator owns authentication, authority,
  sequences, expiry, leases and input release. It uses injectable clocks,
  capture/input interfaces and stores for deterministic tests.
- A Windows capture adapter supplies the primary monitor image and cursor
  position. A Windows input adapter maps normalized coordinates to that monitor
  and invokes SendInput using a bounded key allowlist.
- A registered global Ctrl+Alt+F12 hotkey invokes the same stop path as the
  control window. Failure to register it is visible; the window stop remains.

Do not load SOLIDWORKS to start this agent. Do not proxy the CAD Host or add
shell, filesystem browsing, upload, clipboard, audio or printer endpoints.

## Pairing and credential storage

Only a local action in the Windows control window opens a pairing window.
Generate a cryptographically random 256-bit single-use pairing secret, display
it for copy/paste and expire it after two minutes. Limit attempts and close
pairing after successful enrollment; do not log the secret.

Android accepts an HTTPS workstation URL and that pairing secret. Windows
displays the requested device name and requires local Accept before enrollment
finishes. A device name is a label, not proof of identity. Failed, cancelled,
expired and duplicate requests cannot issue credentials.

Issue a separate random device credential. Store its verifier on Windows using
constant-time verification and protect persisted records with user-scoped DPAPI.
Store the Android credential encrypted using an Android Keystore-backed key.
Never put credentials in URLs, logs, exception messages, backups or screenshots
generated by the application. Pairing and session errors use sanitized messages.

Device revocation invalidates its active sessions immediately and releases
held input. An unpaired or revoked caller cannot obtain frames or inject input.
TLS certificate validation remains enabled; no accept-all certificate option.
The Windows approval UI shows the configured private HTTPS URL; it does not
claim that an arbitrary URL typed on Android has been verified automatically.

## Versioned application protocol

All external requests use HTTPS with authorization headers. The local service
uses loopback HTTP behind Serve. Protocol version 1 has explicit DTOs and
camelCase JSON regression tests in both repositories.

- Pairing: submit secret and device label, poll bounded approval status, obtain
  credential once after Windows acceptance. Pending requests have opaque IDs
  and expire. Polling does not extend the pairing window.
- Session: create, renew, inspect, take control, stop and close.
- Display: retrieve the latest JPEG frame, its dimensions, frame ID, capture
  timestamp, display generation and cursor coordinates.
- Input: submit one ordered pointer/key event associated with the current
  session, authority epoch and display generation.

Use random opaque session IDs and short-lived session tokens. Session tokens
expire after five minutes; renewal requires a still-valid device credential.
One device has control authority at a time. A second connection is rejected
with a clear busy response, rather than silently displacing the first.

Input sequence numbers increase strictly within the current authority epoch.
Reject duplicate, old, out-of-order, wrong-session, expired and wrong-epoch
events before any OS call. Do not automatically replay input after timeouts or
reconnect. The Android input adapter serializes events in a bounded queue and
coalesces unsent pointer moves; it never drops a release silently. Queue failure
ends control and triggers release. Stop is independent of the input queue.

Image dimensions and the monitor mapping share a display generation. Display
configuration change increments the generation, releases held input and refuses
events mapped against old images until Android has a current frame. Coordinates,
button values, key codes, scroll amounts and body/image sizes have explicit
bounds. No arbitrary virtual-key or command string execution.

## First display implementation

Start with bounded JPEG frame refresh over HTTPS, using one request in flight
and a maximum five frames per second while Remote is visible. Capture is shared
per active session; drop obsolete frames rather than queueing them. Cap the
image's longest edge at 1600 pixels and encoded size at 2 MB. Use aspect-fit
mapping on Android, retaining the same rectangle for rendering and input.

This is a modest frame-rate desktop view for menus, forms and initial CAD
interaction. It is not a promised gaming/video stream or smooth 3D camera
experience. Keep capture and display transport boundaries replaceable so a
video stream can be added after measuring the real Windows/mobile connection.
Expose stale-frame and disconnected states clearly. Do not keep showing an old
frame as if it were live. Images remain in memory; no recording or disk cache.

One primary monitor is supported in this version. Multi-monitor selection,
zoom/pan and relative trackpad mode are later increments. Cursor position is
rendered explicitly, since ordinary screen capture may omit the OS cursor.

## Control, stop and connection loss

Live sessions start in Manual/User. Assist and Agent are explicitly unavailable
for live connections until a real AI executor exists; their demo behaviour
remains available only in the demo. Never display simulated AI progress on the
real desktop.

Take Control invalidates the authority epoch, clears queued input and releases
all injected held keys/buttons before granting fresh Manual authority. Stop AI
has no live task to stop in this milestone; the live screen exposes Stop Remote
and Disconnect clearly. Preserve interface seams for later AI interruption.

Windows Stop Remote/hotkey releases input, invalidates the session and refuses
further events. Session close, revocation, expiry, capture/input failure and
process shutdown use the same idempotent release path. Report failed SendInput
calls as failures rather than successful actions.

Android sends a heartbeat once per second while a foreground session is active.
Windows releases held input and invalidates control when three seconds pass
without a valid heartbeat. A watchdog runs independently of capture and request
handling. Release and injection are synchronized so an input racing with stop
cannot execute after authority is revoked. A hung or terminated process cannot
provide this guarantee; do not claim crash-proof OS input release.

Backgrounding the app, losing the rendering session or gesture cancellation
releases held input. Transport failures stop dispatch, clear pending events and
show a disconnected state. Use bounded reconnect delays of 1, 2, 4, 8 and then
15 seconds only while Remote is foreground and the user still wants a connection.
Reconnection creates fresh session authority and requires an explicit Resume
Control action; no old task, held key or queued click resumes. Cancel/Disconnect
stops retries and late callbacks cannot reconnect a cancelled attempt.

The initial agent controls the ordinary interactive desktop only. A locked
desktop, UAC secure desktop, elevated application or unsupported key must produce
an actionable unavailable/unsupported response. Do not request elevation or try
to bypass Windows input restrictions. Ctrl+Alt+Delete is not supported.

## Android integration

Keep CAD repositories and screens independent. Extend AppContainer with a
choice of Demo or Live adapters through the existing session/input/display
boundaries. Add workstation settings and pairing status, plus Forget Device.
Switching endpoints disconnects first and cannot carry credentials to a different
origin. Reject URLs containing userinfo, query credentials or fragments.

Persist only endpoint and encrypted device credentials. Session tokens, frames,
held input and control authority stay in memory. Configuration changes retain
the selected connection; process restart begins disconnected. The UI names the
real workstation and distinguishes Connecting, Connected/View Only, Controlling,
Stale Display and Unavailable with concrete recovery messages.

## Verification and deliverables

Follow TDD for protocol, pairing, state transitions, input validation, ordered
dispatch, stop races, token expiry/revocation, lease timeout, display generations
and retry/cancellation behaviour. Test secret redaction and persistence failure.
Loopback integration uses fake capture/input and does not need SOLIDWORKS or
Windows desktop access. Android tests use a fake HTTPS transport and include
navigation, pairing errors, stale frame, takeover/disconnect and lifecycle release.

Run the full Windows unit suite and non-COM integration checks on Windows CI;
compile capture/input adapters and package the separate executable. Run the full
Android unit suite, build/lint and emulator UI tests. Review the diff and document
exact build/test evidence. Deliver an updated APK and Windows test bundle, with
step-by-step Tailscale, pairing and cleanup instructions.

Windows/mobile acceptance remains explicit and separate: verify real capture,
cursor mapping, click/drag/right-click/scroll/keys, held-input release, local
window/hotkey stop, disconnect/reconnect, monitor change, lock/UAC response,
device revocation and access over phone mobile data. Measure delay/frame rate
before choosing a faster video transport. Do not claim those checks pass in the
Linux workspace or confuse them with the outstanding SOLIDWORKS plate test.

## Not included

Live AI observation/execution, UI Automation, Bambu preparation automation,
starting a print, new CAD capabilities, file transfer, clipboard, unattended
Windows login, public relay hosting, automatic VPN configuration and main merges.
