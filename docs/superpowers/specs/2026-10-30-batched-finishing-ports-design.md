# Batch-port native finishing features

The user wants faster reuse and continued implementation. Keep the current net48 Host/STA, identity, approvals, unit handling and version-28 compile guard. Port the related fillet/chamfer creation and definition-readback code together instead of importing either competing MCP runtime. Reuse the exact face/outer-loop resolver and shared material-operation verifier. This is an independently chosen implementation within the user's authorized scope.

Enable two actual native bridge commands, `FilletEdges` and `ChamferEdges`, for the unique outer loop of an axis-aligned extreme planar face. Preserve existing parameter names (`normalAxis`, `side`, `radiusMm` or `distanceMm`). Constant-radius simple fillets and 45-degree angle-distance chamfers only; tangent propagation is disabled. Selected edges must be straight, with two orthogonal planar adjacent faces. Capture their original line geometry before mutation. Inner/hole edges are excluded by the existing resolver.

First safe execution scope: only an unsaved part created by this bridge's NewPart in its current bound document context. Generic bindings, opened/saved parts, null native paths and quarantined parts are rejected before selection or modelling. Generic bind/open/clear/new-execution transitions revoke eligibility. A new NewPart restores eligibility. Any failure after a potentially mutating native call quarantines finishing for that part; no retry or ad-hoc feature deletion is permitted. Failure reports possible partial changes and no rollback. Existing saved-part edits continue through the established checkpointed path; this increment does not generalize that path or expose finishing in the AI planner.

Reuse one lifecycle for both ports: validate/context gate → exact resolver and edge preflight → capture feature inventory and material → select exact edges with verified identity/count/mark → one API call → native type/rebuild checks → scalar definition and geometry checks → material removal with one body preserved → meaningful unique naming → inventory difference proving exactly one added feature → structured result. Keep existing boss/cut call semantics intact when extending the shared verifier.

Definition verification requires correct kind, uniform radius, requested size, requested edge count, disabled tangent propagation and 45 degrees for chamfers. Fillets need measured analytic round-face radius evidence; no freeform/unmeasured success fallback. Chamfers need independently measured planar-face boundary offsets for each original edge (two orthogonal legs at the requested distance). The port of these checks may be stricter than upstream and must report unsupported geometry rather than guess.

Add read-only `GetEdgeFinishingFeatures` to inspect native definitions after save/reopen. It must not call AccessSelections, select, rebuild or mutate. Keep scalar/count-readback limitations explicit: native acceptance must prove these reads work in installed SW2020. Hashes remain evidence, not selection authority. Add opt-in native tests building fresh synthetic plate/through-hole stock using supported origin-plane sketches; finish opposite faces, save/reopen, read definitions and verify body geometry/hole preservation. Opened saved files must reject further finishing.
